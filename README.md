# post-collector 使用手册

## 这是什么

一个装在自己机器上的内容收纳工具。它从**你自己拥有或已获明确授权**的来源（自建频道、自己的账号导出、你管理的群、RSS 等）把图文内容收进来，去重、清理、打标签，然后让你按标签、关键词、来源、时间、类型把它们搜出来。

它解决的是「东西太多、散得到处都是、想找的时候找不到」。它不是公开图站，也不做内容分发：默认只监听本机或内网，默认不把任何内容发到外部服务。

## 它刻意不做的事

下面这些不是「以后再说」，而是设计上明确排除，写在这里免得你反复期待：

- 不绕过登录、验证码、平台限流，不抓非公开内容；
- 不做公开分享站点，不做内容再分发；
- 不做多人 SaaS，不做实时聊天客户端；
- 不给匿名提报者任何账号、历史记录或检索能力；
- 不把内容送去第三方 AI：当前版本连外发代码路径都不存在。

## 现在能用到什么程度

这一版是**骨架**，先把地基、数据结构和接口画对。功能按 DESIGN.md 的路线图分三阶段交付，当前进度如下：

| 能力 | 当前状态 |
| --- | --- |
| 目录结构、13 个可替换的接口、数据库建表脚本、设置项声明 | 已完成 |
| 环境体检命令 `pc doctor` | 已完成，现在就能用 |
| 接口服务（存活检查、运行模式查询） | 已完成，需先装依赖 |
| 采集来源、去重、打标、检索、Web 界面 | **尚未实现**，见文末「当前版本还不能做什么」 |

也就是说：现在可以把环境搭好、把数据库建起来、把服务点着，但还搜不到东西。

## 你需要准备什么

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 机器 | 4 核 CPU / 8 GB 内存起，SSD 用于数据库与近期媒体 | 有 GPU 更好，没有也能跑，只是打标慢一些 |
| 磁盘 | 按每年约 55 GB 估（日增 100 条、平均 1.5 MB/条） | 系统内置滚动删除，可把增长压平 |
| 运行时 | Docker（推荐），或 Python 3.12+ 与 uv | 本机当前未装 Docker，容器路径尚未验证 |
| 来源 | 至少一个你拥有或已获授权的来源 | 每个来源都要有「凭证 + 授权范围 + 授权证明」，三者齐备才入库 |
| 网络 | 首次安装依赖需要联网；日常运行不需要 | 没有任何功能以外发为前提 |

## 五分钟跑起来

以下命令都在仓库根目录执行。只有第 3 步需要 Docker，另外四步不需要。

1. 安装依赖。它会生成 `uv.lock`（这个文件需要提交到版本库），并一并装好开发用的工具：

   ```bash
   uv sync                      # 只想要运行时依赖：uv sync --no-dev
   ```

2. 体检。确认环境与文件齐全：

   ```bash
   uv run python -m pc doctor   # 等价写法：uv run pc doctor
   ```

   还没装依赖时也能体检，那种情况下用 `PYTHONPATH=src python -m pc doctor`。但请**不要**直接跑 `python -m pc doctor`——系统 Python 看不到这个项目，会报 `No module named pc`。

3. 建立数据库。用容器起 PostgreSQL，再应用建表脚本：

   ```bash
   cp .env.example .env          # 先把里面的 POSTGRES_PASSWORD 改掉
   docker compose up -d db
   psql "$PC__DB__DSN" -v ON_ERROR_STOP=1 -f migrations/0001_init.sql
   ```

   两点注意：这个脚本尚未在真实数据库上执行过；它是**整条语句执行**的写法，请用 `psql -f`，不要自己按分号切分。

4. 启动服务：

   ```bash
   uv run uvicorn pc.api.app:create_app --factory --port 8080
   ```

5. 确认它在跑：

   | 地址 | 用途 |
   | --- | --- |
   | `http://127.0.0.1:8080/` | 索引页：版本、当前阶段、可用端点 |
   | `http://127.0.0.1:8080/healthz` | 存活与版本 |
   | `http://127.0.0.1:8080/api/v1/meta` | 当前运行模式，含 `egress_enabled: false` |
   | `http://127.0.0.1:8080/docs` | 自动生成的接口文档 |

   没有 Docker 也可以跳过第 3 步，直接跑第 4、5 步——服务和体检命令都不依赖数据库。

## 数据存在哪

所有运行时产物都在仓库的 `data/` 下，全部不会进版本库（`models/` 同理）：

```
post-collector/
├── data/
│   ├── db/            PostgreSQL 数据目录（事实源）
│   ├── media/         媒体本体，按内容哈希分片存放（ab/cd/<sha256>）
│   ├── cold/          冷层：较早或低频的媒体
│   ├── quarantine/    匿名提报隔离区，与主存储物理分离，按期限自动清理
│   └── backup/        备份目标，可以指向 NAS
├── models/            本地模型权重（阶段 1 起自动下载并校验）
├── config/            配置：能改的都在这两个文件里
└── migrations/        建表脚本，按序号追加
```

一件事需要说清楚：**数据库和媒体目录是唯一必须认真备份的两样东西**，其它一切（检索索引、向量、派生标签）都能从这两样重建。另外，删除功能不会追溯清理已有的备份，所以「删除后最长 N 天内仍可能存在于备份中」这句必须写进你的隐私策略。

## 日常操作

| 我想… | 怎么做 |
| --- | --- |
| 看现在状态如何 | `python -m pc doctor` |
| 启动 / 停止服务 | `docker compose up -d app` / `docker compose down` |
| 看最近发生了什么 | 界面按钮与结构化日志在阶段 1 加入；当前看容器日志 |
| 换端口 | 启动时加 `--port 8081`，或改 `docker-compose.yml` 的端口映射 |
| 确认没有内容被外发 | `GET /api/v1/meta` 的 `egress_enabled` 恒为 `false`；当前版本没有外发代码路径 |
| 加一个采集来源 | 阶段 1 才有界面与连接器；先按 DESIGN.md §1.3 选接入方式 |

## 参数怎么调

同一个参数只有一个来源，避免出现「改了文件没生效」这类最难查的问题：

| 层 | 位置 | 改它的方式 | 生效 |
| --- | --- | --- | --- |
| 设置页 | 数据库 `setting` 表，字段说明来自 `config/settings-registry.yaml` | 界面点选，中文标签 + 一句大白话说明 + 改了会怎样 | 立刻生效，不用重启 |
| 开发配置 | `config/app.yaml` | 直接编辑（带注释） | 校验通过后热重载 |
| 部署配置 | `docker-compose.yml` / `.env` | 编辑后重启容器 | 需要重启 |

规则是：第一次启动时，`config/app.yaml` 里的 `defaults` 段会被用来给数据库写入初始值；此后一切以数据库为准。想改默认值就改注册表，别去改已经初始化过的实例。

每个设置项都能用环境变量临时覆盖，形式为 `PC__` 加双下划线，例如把检索每页条数改成 80：

```bash
PC__SEARCH__DEFAULT_PAGE_SIZE=80
```

现在能调的设置项：相似图片判定严格度、AI 参与程度、内容库最大占用、检索每页条数、匿名提报开关、全局仅本地开关。数据库地址、端口、并发数这类「改错了后果不容易一句话说清」的参数，刻意只留在配置文件里，不放界面。

## 默认的隐私与安全状态

| 默认行为 | 含义 |
| --- | --- |
| 不外发 | 当前版本没有把内容送往外部 AI 的代码路径，可用 meta 接口自查 |
| 只用本机模型 | AI 参与程度默认「仅本机模型」，也可以切到「完全不参与」纯手动整理 |
| 匿名提报关闭 | 打开后内容先进隔离区，审查通过前不进检索、不入库、不下载 |
| 受限内容不进检索 | 命中即隔离，不生成缩略图，不进任何处理流程，仅提示你处理 |
| 不存访客原始 IP | 只存带盐哈希，够用于限流与滥用溯源 |
| 链接默认只记录不抓取 | 抓取要显式开启，且走禁内网、限重定向、限大小的沙箱抓取器 |

## 出问题了怎么办

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| `doctor` 报某个文件不存在 | 不在仓库根目录运行 | 回到仓库根，或用 `--root` 指定路径 |
| `python -m pc doctor` 报 `No module named pc` | 用的是系统 Python，没走项目虚拟环境 | 加 `uv run`：`uv run python -m pc doctor`；或临时设 `PYTHONPATH=src` |
| `config show` 提示缺 PyYAML | 还没装依赖 | 跑 `uv sync` |
| `config show` 退出码 3 | 该功能骨架阶段尚未实现 | 属预期；实现指引见 DESIGN.md §6.2 |
| 启动报端口被占用 | 8080 有别的程序 | 换端口 `--port 8081` |
| `psql` 连不上 | 数据库没起，或密码没改 | `docker compose ps` 看状态，核对 `.env` 里的连接串 |
| 老终端里中文显示成方块 | 终端编码不是 UTF-8 | 命令输出已强制 UTF-8；换个终端或执行 `chcp 65001` |
| 报错看不懂 | 缺少上下文 | 把 `doctor` 的输出贴进 issue，它已包含脱敏后的环境信息 |

## 当前版本还不能做什么

这些不是「忘了写」，而是按阶段排期：链接自动抓取、AI 外发、向量检索、以图搜图、多租户、Meilisearch 与 MinIO、Web 界面、后台 worker 与调度器、备份脚本、测试套件。

阶段 1 要做的是打通第一个可用闭环：**采集 → 安全扫描与去重 → 存储 → 打标 → 检索 → 人工纠错**，全部本机运行。它的验收标准写在 DESIGN.md §9，其中两条与安全直接相关，会用断言级测试守住：匿名提报在审查前零副作用；全库不存在任何外发调用路径。

## 落地前需要你确认的事

技术上能做的已经做了，剩下的是**只有你能拍板**的部分。建议在正式导入数据前逐项过一遍 DESIGN.md 附录 A：

- 目标平台的接口条款、Bot 权限范围、历史消息可读性、速率限制；
- 所选模型权重的许可证是否允许你的使用场景；
- 你所在司法辖区对采集、存储、处理他人内容与个人信息的要求；
- 如果打算开放匿名提报入口：你可能因此承担内容存储与下架相关的义务，先确认再开；
- 滚动删除与删除权的冲突：硬删后仍会保留内容哈希（用于防止同一内容被反复导入），确认这在你这里可接受。

想改代码、加模块、写迁移，请先读 [`AGENTS.md`](AGENTS.md)；想知道某个设计为什么是这样，读 [`DESIGN.md`](DESIGN.md)。
